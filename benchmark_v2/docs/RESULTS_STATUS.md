# Results Status

> **Last updated**: 2026-08-02

## Current State

The CSV files in `event_graph/reports/` were generated by previous versions
of the benchmark code that contained several critical issues (see below).
**These results are retained for historical traceability but must not be
used as final evidence.**

### Issues Fixed (code-level)

| # | Issue | Impact |
|:--|:------|:-------|
| 1 | `structural_core.py` / `adversarial_core.py` imported non-existent `compute_iot` | Modules could not run; results came from an earlier, untracked code version |
| 2 | `extract_station_events` over-merged events (double `window_minutes` gap) | IoL/IoU systematically inflated for stations with dense bursts |
| 3 | Temporal baseline did not merge overlapping bursts | Unfair comparison: graph baseline saw merged events, temporal saw fragments |
| 4 | Multiple duplicate `build_graph` implementations across modules | Risk of subtle behavioural drift between tests |
| 5 | `Purity` metric name collision (ClusterPurity vs MatchPurity) | Values 54% and 83% reported under the same name in different files |
| 6 | `forbidden_edge_rate` included same-antenna pairs in denominator | Metric was artificially deflated |
| 7 | `real_beats_null2` used `!=` instead of a meaningful statistical test | Any floating-point difference would pass |

### Archived Results

Pre-fix results are preserved in:
```
event_graph/reports/_archive_pre_fix/
```

### Re-run Required

After the consistency fixes, a full re-run of the benchmark suite is
required to produce valid, internally consistent results.  Until then,
the numerical values in the documentation files (`ablation_ladder.md`,
`eg_loso_metric_revision.md`, `station_contribution_analysis.md`) reflect
the **pre-fix** execution and are labelled accordingly.

### Methodology Validated

The *methodology* described in the documents is sound.  The fixes
strengthen the benchmark by:

1. Ensuring a single mathematical model is tested by multiple experiments.
2. Providing a fair temporal baseline for the Graph vs Temporal comparison.
3. Eliminating metric ambiguity (ClusterPurity vs MatchPurity).
